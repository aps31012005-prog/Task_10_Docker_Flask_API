# Task 10: Containerizing Flask Deep Learning API

## 1. Introduction

This project demonstrates the containerization of a Flask-based deep learning API using Docker.

The application uses a pre-trained CIFAR-10 image classification model developed in the previous tasks. The Flask API provides an endpoint for uploading an image and obtaining a predicted CIFAR-10 class along with the prediction confidence.

Docker is used to package the Flask application, Python dependencies, and trained deep learning model into a portable container.

The main objectives of this task are:

- To verify the prediction generated by the trained model.

6. Flask API

The Flask application is implemented in flask_api.py.

The application loads the trained CIFAR-10 model from:

model/cifar10_cnn.keras

The API provides two main routes.

Home Endpoint
GET /

This endpoint verifies that the Flask API is running.

Example response:

{
    "endpoint": "/predict",
    "message": "CIFAR-10 Flask Prediction API is running",
    "method": "POST"
}
Prediction Endpoint
POST /predict

The endpoint accepts an uploaded image using the form field:

image

The image is converted to RGB, resized to 32 × 32 pixels, normalized, and passed to the trained CNN model.

8. Image Preprocessing

The uploaded image is processed before prediction.

The following preprocessing operations are performed:

The uploaded image is opened using Pillow.
The image is converted to RGB format.
The image is resized to 32 × 32 pixels.
The image is converted into a NumPy array.
Pixel values are normalized by dividing by 255.
A batch dimension is added.
The processed image is passed to the TensorFlow model.

17. Docker Image Optimization

Several Docker optimization practices were implemented.

Lightweight Base Image

The project uses:

FROM python:3.11-slim

instead of a full Python image.

No pip Cache

Dependencies are installed using:

RUN pip install --no-cache-dir -r requirements.txt

This prevents pip package caches from being unnecessarily stored in the image.

Docker Layer Caching

The requirements file is copied before the application source code:

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

This allows Docker to reuse the dependency layer when application code changes.

Dockerignore

The .dockerignore file prevents unnecessary files such as:

Python cache files
Git files
VS Code files
Screenshots
README files

from being included in the Docker build context.

18. Docker Image History

The Docker image history was inspected using:

docker image history task10-flask-api:latest

The largest layer was the dependency installation layer.

The TensorFlow and related Python packages accounted for approximately 2.25 GB of the image layer shown in the history.

The model layer was approximately 3.84 MB.

This analysis helped identify the major contributor to image size.

710 MB
20. Optimization Observation

The optimized image did not show an additional reduction in reported image size.

This is because the original Dockerfile had already implemented several standard optimization techniques, including:

A slim Python base image.
pip cache removal.
Docker layer caching.
A .dockerignore file.
A minimal application build context.

Therefore, rebuilding the same optimized configuration under a different image tag did not create a smaller binary image.

The optimization was therefore evaluated through Dockerfile practices and image-layer analysis rather than artificially reducing the image size at the expense of application functionality.
